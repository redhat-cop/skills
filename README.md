# redhat-cop/skills

Field-contributed agent skills for Red Hat technologies — reusable SKILL.md-style automations for AI coding agents.

Skills follow the open [Agent Skills specification](https://agentskills.io/specification) (a skill is a folder with a `SKILL.md`), so they work across harnesses — Claude Code, Codex, Cursor, OpenCode, Pi, Hermes Agent, OpenClaw, OpenHands, DeepSeek and more. No marketplace lock-in: install straight from this repo.

## Install

```bash
npx skills add redhat-cop/skills --skill <skill-name>
```

The [skills CLI](https://github.com/vercel-labs/skills) auto-detects installed agents. Most harnesses read the same shared project directory, so one install lights up several at once — then target agents explicitly if you prefer:

| Harness | Install flag | Skills land in (project) |
|---|---|---|
| Claude Code | `-a claude-code` | `.claude/skills/` |
| Codex | `-a codex` | `.agents/skills/` |
| Cursor | `-a cursor` | `.agents/skills/` |
| OpenCode | `-a opencode` | `.agents/skills/` |
| Pi | `-a pi` | `.agents/skills/` |
| Oh My Pi | *(pi / codex providers)* | `.agents/skills/` |
| Hermes Agent | `-a hermes-agent` | `.hermes/skills/` |
| OpenClaw | `-a openclaw` | `skills/` |
| OpenHands | `-a openhands` | `.openhands/skills/` |
| DeepSeek (Deep Code) | *(no flag — native `.agents/skills/` reader)* | `.agents/skills/` or `.dsh/skills/` |

> **Shared directory:** Codex, Cursor, OpenCode, Pi, Oh My Pi and DeepSeek all read `.agents/skills/` (project) or `~/.agents/skills/` (global). Installing once there covers all of them.

Other handy forms: `npx skills add redhat-cop/skills --list` (browse), `--skill '*'` (everything), `-g` (global scope), `owner/repo@v1.2.3` (pin a tag).

## Authoring a skill

Start with [CONTRIBUTING.md](CONTRIBUTING.md) — it covers the frontmatter contract, house rules, quality bar, and the PR flow. Copy `template/skill-name/` to get a valid skeleton, or let your agent do it: the repo's [AGENTS.md](AGENTS.md) teaches agents the conventions.

## Governance

Review model, approval tiers and maintainers live in [MAINTAINERS.md](MAINTAINERS.md); per-skill ownership is enforced through [CODEOWNERS](CODEOWNERS) and CI. PRs themselves are processed by the repo's PR agent (phase cards, guarded merges) — see the [PR workflow](docs/pages/pr-workflow.md).
